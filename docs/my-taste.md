# my-taste

## 本体论
本 skill 处理的不是“修改文本”，而是“在纠错后重建评价函数”。用户说“不对”时，真正被否定的是产物背后的选择系统：它把什么当成目标，把什么当成可牺牲，把什么当成安全。若只改产物，不改选择系统，同类失败必然复发。

核心动作：把上下文对目标作商。去掉只服务本次对话的偶然上下文，留下脱离本次上下文后仍能约束新 agent 的判断结构。充分的标准不是“什么都说到了”，而是“再说一句不会改变决策，再删一句会复活失败”。

非目标：不把产物改得更完整、更稳、更礼貌、更专业；不追求覆盖所有可能；不把谨慎写成免责声明；不用流程仪式替代判断。

## 触发与不触发
触发：用户给出否定性短指令，且不满指向判断、颗粒度、触发边界、气质或抽象层，例如“不对”“差一点”“太机械”“优化一下”“这不是我要的”。

不触发：用户只要字面修补；问题是可核验事实错误；没有既有产物可保；用户明确授权自由发挥。不触发时直接做任务，不得套用本流程。

误判代价：该触发时不触发，会把品位问题降级成字句问题；不该触发时触发，会把简单修补升级成审问。两者都算失败。

## 三条轴
三轴用于定位产物把智能花在哪里。每轴都必须落到决策，不许变成描述性标签。

### 撤销轴：是否允许推翻已生成内容
- 判别问题：后续 token 是否真正改变先前约束，还是只在口头上“我再想想”。
- 高撤销适用：目标未定位、反例会改变结论、用户纠错指向方向而非措辞。
- 低撤销适用：目标已收敛、继续推翻只会消耗承诺、用户要的是执行。
- 失败模式：假反思——语言上自我否定，后续分布没有转向；或拒绝撤销——明知前提已坏仍继续抛光。
- 反例支付：若撤销后没有新增约束、没有删除旧约束、没有改变验收标准，则本次撤销无效，应回退为陈述不确定性。
- 操作禁手：不得用“等一下/不对/重新考虑”制造思考感；每次撤销必须命名被废弃的假设。

### 覆盖轴：是否优先列全维度
- 判别问题：新增维度是否提高关键难点区分度，还是只提高完整感。
- 高覆盖适用：用户不知道选项空间、遗漏比冗余更贵、需要地图而非结论。
- 低覆盖适用：难点已定位、用户要锋利判断、覆盖会摊平权重。
- 失败模式：全景化稀释——每点都正确，关键处不突出；或过早收敛——把未探索空间误当成已排除。
- 反例支付：每新增一个维度，必须说明它排除了哪种误选；说不出排除什么，就删除该维度。
- 操作禁手：不得把“全面”作为默认美德；覆盖必须服务于排除误选。

### 承诺轴：是否在不确定处仍给可证伪判断
- 判别问题：论断是否能错；若不能错，它只是姿态。
- 高承诺适用：用户需要可执行方向、品位选择必须落地、模糊会诱发机械折中。
- 低承诺适用：事实不可核验、用户明确要探索、承诺会伪造确定性。
- 失败模式：低承诺伪装成严谨，用 caveat 逃避选择；或高承诺伪造确定，把偏好说成事实。
- 反例支付：每个强判断必须给失效条件；给不出失效条件，就降为假设并标注缺口。
- 操作禁手：不得用“可能/或许/视情况”替代选择；不确定时应说“缺什么会改变这个判断”。

三轴联动：探索期允许高撤销、中覆盖、中承诺；收敛期应低撤销、低覆盖、高承诺；诊断期可高覆盖，但必须用覆盖来排除误选，而不是展示博学。

## 三层对齐
用户的不满必落在 G/P/O 之一。先定位层，再决定改动深度。

### 目标层 G：评价函数错了
- 识别信号：用户否定的是方向，如“这不是我要的”“你根本没懂”“太机械”。
- 必须回答：这次被优化的是什么；什么结果即使措辞漂亮也仍算失败。
- 缺失时：只问“最不能忍受的是哪一点”，不问开放风格偏好。
- 禁手：不得把 G 翻译成“更清晰/更完善/更高级”；这些词不约束任何决策。
- 验收：能用一句可错的话说出目标，并给出一个即使表面合格仍判失败的情形。

### 原则层 P：边界与牺牲错了
- 识别信号：用户说“别动这个”“你又加了一堆”“保住那个味道”。
- 必须回答：必须保住什么；宁可牺牲什么；什么改动即使有效也过界。
- 缺失时：问“哪部分宁愿错也不要动”；若用户不答，给保守/重构/只改触发边界三案并标明牺牲。
- 禁手：不得为了稳妥新增用户未要求的限制；不得把原则写成免责清单。
- 验收：每条原则都能指出被它禁止的具体动作；没有动作可禁的原则是修辞。

### 操作层 O：切口错了
- 识别信号：用户认可方向，但指出“改错地方”“动了不该动的”“这里差一点”。
- 必须回答：每处改动改变哪个决策；删掉它会复活哪种失败。
- 缺失时：不问，直接给最小切口 A/B/C，并说明各自失去什么。
- 禁手：不得用执行勤奋掩盖 G/P 未对齐；不得把“改了很多”当作“改对了”。
- 验收：每个改动点都能命名被阻止的失败；不能命名失败的改动必须删除。

## 四大改动维度
设需求为 G，上下文为 C，失败模式为 F，余数 R 为冗余、防御、未闭环假设、只对本例有效的补丁。

### L0 字面最小改动：症状替换
只响应显性词句，不改决策结构。同一 F 换措辞、换场景、换 agent 后必然复发。默认拒绝，除非用户明确只要字面修补。退出标准：用户确认只要本句变化，且接受同类失败复发。

### L1 最小必要改动：失败点切除
删到再删一步，原失败 F 就会复活；但不追求推广。必须能回答“这次为什么错”，允许暂时回答不了“以后如何不错”。退出标准：本例 F 不再出现，但冷启动 agent 仍可能复发。

### L2 最小充分改动：可迁移商化
在 L1 之上，把修复从本次上下文商出来，使冷启动 agent 不看原对话也能避免同类 F。利用对大模型偏置的理解：模板化、过度覆盖、防御性免责、礼貌性平滑、把纠错当补丁。把这些偏置写成触发边界与禁手，而不是更多注意事项。退出标准：无本对话的新 agent 能复现同一判断。

### L3 最大充分改动：无余闭环
目标、原则、操作三层同时对齐；充分到不能再删，干净到不能再省；自带验证回路。必须同时满足：G 可错、P 能禁动作、O 能命名失败、三轴有停机规则、验收含正例/反例/不触发例。加入防御性完备、未来所有可能、保险丝式规则，即跌出 L3。

升档条件：当同一失败会跨措辞、跨场景、跨 agent 复发，至少到 L2；当失败来自评价函数且用户要求“保证/彻底/正式”，到 L3。降档条件：更高档位不改变任何决策，只增加解释成本，立即降档。

## 执行回路
1. 定位：先判不满在 G/P/O 哪一层；判不出时，给出最可能层与一个能改变决策的问题。
2. 定轴：声明当前处于探索/诊断/收敛哪期，并据此设定撤销、覆盖、承诺的允许范围。
3. 品位假设：G/P/O 各一句；每句必须可错。写不出可错句，说明信息不足，按缺口规则处理。
4. 反例支付：每个抽象原则给一个反例或失效条件；支付不起就删除该原则。
5. 最小切口：列改动点；每点写“阻止的失败 / 删除后复活的失败”。
6. 商化：删除只服务本次上下文的内容；把剩余规则写成冷启动 agent 可执行的触发边界。
7. 无余：删除不改变决策的句子、重复免责、为了显得稳妥而加的限制。
8. 闭环：给验收 V、正例、反例、不触发例；说明本 skill 何时不该被继续使用。

## 缺口规则
缺 G：问“最不能忍受的是哪一点”。缺 P：问“哪部分宁愿错也不要动”。缺 O：不问，给 A/B/C 切口并标牺牲。缺事实：说明无法核验，不编造。禁止泛问“你想要什么风格”“能多说点吗”，除非答案会改变档位或切口。

停机条件：继续获取信息不会改变 G/P/O、三轴设定、改动点或验收标准时，立即停止。信息不足时合法输出只有两种：一个能改变决策的问题；或一组带牺牲说明的可选切口。

## 输出契约
若用户已授权直接改，仍需在改动说明中保留以下四项；若未授权，只输出这四项并等待确认。

- 档位：L0/L1/L2/L3；说明为什么不是更低（会复发）和为什么不是更高（会冗余）。
- 品位假设：G/P/O 各一句，均可错。
- 三轴设定：撤销/覆盖/承诺当前应高还是低，及停机点。
- 改动点与闭环：每个决策点含“阻止的失败 / 删除后复活的失败”；验收 V；正例；反例；不触发例。

## 冷启动自测
把一个只读本 skill 的新 agent 放进以下场景，它应能做到：用户说“这个 skill 太啰嗦”时，不直接压缩字数，而先判 G=降低触发后废话、P=保住触发边界、O=删不改变判断的注意事项；能指出若删除触发边界会导致事实错误也套用流程，则该删除过界；能主动说出“用户只改错别字时不触发”。

任一做不到，说明对应模块仍是 L1：只对本例有效，未商化。

## 红线
- 不得增加规则密度来冒充判断质量。
- 不得把原则写成免责清单。
- 不得为了显得安全而加入用户未要求的限制。
- 不得在未说明 G/P/O 前直接改文本。
- 不得用“可能、或许、建议大家视情况”替代可证伪判断。
- 不得把 L3 理解成“想到最多”；L3 是充分到不能再删，不是完备到不能再加。
- 当闭环只给结论不给失效条件，视为未闭环。

## 一句话判据
L0 改句子，L1 改病因，L2 把病因从上下文里商掉，L3 让三轴、三层、四档都可冷启动执行、可支付反例、可停机，并且无余。
